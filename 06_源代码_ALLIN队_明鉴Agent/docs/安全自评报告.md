# 一、评估结论

评估对象为明鉴 Agent 2.0.0 本地竞赛原型。系统实现真实本地大模型规划、三级权限、TOTP、原子账本和审计链，但只适合合成数据演示，不满足真实银行生产安全要求。

# 二、权限分级

| 级别 | 实现 | 验证结果 |
| --- | --- | --- |
| 绿色 | 余额与账单只读自动执行 | 不产生资金变化 |
| 黄色 | 小额转账、订阅操作需审阅确认 | 无审阅令牌或参数变化均拒绝 |
| 红色 | 日累计超过1000元需手机TOTP | 未绑定、错误或重放动态码均拒绝 |

权限由服务端按执行瞬间的日累计和账户状态计算，不能由模型或前端指定。并发计划也会在同一数据库事务中重新分级。

# 三、威胁与控制

| 风险 | 已实施控制 | 剩余风险 |
| --- | --- | --- |
| 模型幻觉成功 | 模型只规划；成功信息只取工具回执 | 小模型仍可能误解意图 |
| Prompt注入 | 系统提示、JSON Schema、工具白名单、服务端策略 | 未做大规模红队评测 |
| 参数偷换 | 版本化计划、授权差异、旧令牌失效 | 本地管理员仍可改程序 |
| 重复扣款 | 节点状态、唯一约束、SQLite事务 | 未接真实清算对账 |
| 越级操作 | 执行时重算风险，红色TOTP | 未接人脸/U盾和设备证明 |
| 跨站请求 | 本机绑定、Host/Origin/CSRF检查 | 本机恶意高权限软件仍可攻击 |
| 审计篡改 | SHA-256链，校验失败熔断 | 无外部时间戳或异地锚定 |
| 敏感数据泄露 | 不采集真实银行数据，对话不出本机 | SQLite和TOTP密钥未硬件加密 |

# 四、模型隔离

Qwen3 与 llama.cpp 只监听 127.0.0.1，接口使用启动器生成的随机密钥。模型只能返回五类结构化候选动作，不能运行代码、SQL、系统命令或访问任意网址。模型服务故障时返回明确错误，系统不会回退到伪装成AI的规则结果。

# 五、验证证据

39/39 自动化用例通过，覆盖累计额度边界、并发升级、幂等、防重放、过期、原子回滚、会话隔离、DAG校验、审计篡改及授权快照。6/6真实模型语义用例通过，覆盖复合业务、账单语义、订阅取消、缺参澄清、跨轮补全及否定意图。测试仅证明列出的当前行为，不等同于银行安全认证。

# 六、上线前必须补齐

真实接入需由持牌银行提供受控API、客户身份认证、交易签名、TLS与密钥管理、反洗钱和反欺诈引擎、人工审核、灾备、隐私影响评估及渗透测试。不得把本竞赛沙箱直接暴露到公网或用于真实资金。
